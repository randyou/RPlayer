# RPlayer 后续开发路线图

基线：v0.13.3（2026-11-24）
测试基线：`cargo test --release` 54 passed
目标平台：Windows 10/11 x64，本地优先、离线可用

## 1. 现状判断

RPlayer 已经完成从“能播放”到“日常可用”的主要闭环：

- 本地曲库、增量扫描、文件夹监听、M3U 导入。
- 专辑/艺术家/收藏/最近播放/播放队列/歌单/智能歌单。
- 无缝播放、EQ、ReplayGain、五态播放模式、SMTC、全局媒体键。
- 歌词获取、歌词编辑、逐句时间编辑、自定义歌词优先。
- 桌面歌词、迷你播放器、六套主题、页面与控件动效。
- 标签编辑、批量标签、批量撤销、重复歌曲检查、曲库健康检查。
- CUE 虚拟曲目、CUE 重定位、CUE 分段播放。
- 数据备份/恢复：核心 JSON/SQLite、可选媒体缓存、恢复前快照与校验回滚。

当前主要短板不在“功能数量”，而在以下四类：

1. **发布一致性**：v0.13.0 已把版本收敛到 `Cargo.toml`，后续发布只需跑检查清单。
2. **CUE 真实回归**：v0.13.1 已补真实时长、路径、边界和会话迁移测试；多 `FILE` CUE 仍明确不支持。
3. **数据安全**：v0.13.2 已补一键备份/恢复、恢复前快照和损坏备份校验；后续仍需关注迁移与长期兼容。
4. **可访问性与细节**：全局键盘焦点环、Tab 顺序仍未完成；重复歌曲检查只能看不能处理。

## 2. 优先级原则

- **P0 正确性与数据安全**：会导致播错、丢数据或发布物不一致的问题先修。
- **P1 日常效率**：重复歌曲清理、备份恢复、键盘操作。
- **P2 体验与规模**：大曲库性能、输出设备、视觉打磨。
- 每个版本只做一个主题，保持可回滚、可验收。
- 不引入云端依赖，不改变“本地文件是唯一音乐来源”的边界。

## 3. 版本路线

### v0.13.0 发布工程与文档校准（S）

**要解决的问题**

- `build.rs:13-14` 仍是 `0.12.6.0`，资源管理器里看到的 exe 版本过期。
- `Cargo.toml`、`src/app/sidebar.rs`、`src/app/settings.rs`、`src/app/dialogs.rs` 各自维护版本字符串。
- `README.md` 的特性列表停留在 v0.7 左右，没有覆盖桌面歌词、CUE、歌词编辑、重复检查等。
- `AGENTS.md` 的歌词优先级仍是旧规则，和 v0.10.6 的自定义歌词优先不一致。

**工作项**

- 用 `env!("CARGO_PKG_VERSION")` 统一 UI 版本显示，删除硬编码。
- `build.rs` 从 `CARGO_PKG_VERSION` 生成 `FileVersion` / `ProductVersion`，不再手写。
- 增加 `docs/RELEASE_CHECKLIST.md`：测试、构建、版本核对、打包、SHA-256、提交。
- 更新 README 特性列表和 AGENTS 的歌词优先级、模块表。
- 可选：增加 `scripts/release.ps1`，一条命令完成测试、构建、复制 dist、压缩、算哈希。

**验收**

- 侧栏、设置、关于、exe 属性中的版本完全一致。
- `cargo test --release` 通过，release 构建通过。
- 新 checklist 能独立指导一次发布。

### v0.13.1 CUE 真实回归与边界补强（M）

**状态：已完成（2026-11-24）**

**要解决的问题**

- v0.12.9 的 CUE 分段逻辑只有纯函数测试，没有真实 CUE 文件的播放/seek/切歌验证。
- CUE 的 `INDEX 00` 前奏、多个 `FILE`、路径带空格、GBK 编码等变体覆盖不足。
- 真实 CUE 专辑的会话恢复没有回归样本。

**工作项**

- 测试中用临时目录生成小型 WAV + CUE，不提交大二进制 fixture。
- 覆盖：第二首从 `cue_start` 开始、进度从 0、到 `cue_end` 自动下一首、seek 后仍按单曲区间。
- 增加 CUE 会话恢复测试：schema 1 的整轨位置迁移到 schema 2 的单曲位置。
- 评估并实现 `INDEX 00`（前奏/隐藏轨）策略；不支持时在文档中明确。
- 手工验收：临时添加 CUE 文件夹，播放、seek、切歌、重启恢复，完成后清理测试目录。

**验收**

- 真实 CUE 专辑完整播放一遍不串轨。
- 普通曲目的播放、seek、gapless、会话恢复无回归。
- 测试基线从 43 提升到 46+。

### v0.13.2 数据备份与恢复（M，已完成）

**要解决的问题**

- 用户换机、重装或误操作后，曲库/歌单/统计没有正式恢复入口。
- 数据库迁移只有自动 `.bak`，没有用户可操作的导出包。

**工作项**

- 设置页增加“备份数据 / 恢复数据”。
- 备份内容：`library.json`、`library.db`、`playback_stats.json`、`session.json`；封面/歌词缓存可选。
- 恢复前自动备份当前数据，恢复后校验 JSON/SQLite 可读，失败则回滚。
- 增加“只恢复设置，不恢复曲库”选项，避免路径冲突。
- 文档说明备份包结构和恢复边界。

**验收**

- 备份后清空数据目录，恢复能还原歌单、收藏、设置和统计。
- 损坏备份不会覆盖现有数据。
- 恢复失败有明确提示和回滚。

### v0.13.3 重复歌曲清理（M，已完成）

**要解决的问题**

- v0.12.0 的重复歌曲窗口只能列出分组，不能处理。
- 用户需要逐组保留一首、移除其余条目，或打开文件位置确认。

**工作项**

- 每组显示标题、艺术家、专辑、格式、时长、路径。
- 操作：“仅保留此首”“从曲库移除其余”“在文件夹中显示”。
- 移除只删数据库记录，不删除磁盘文件；二次确认并说明。
- 支持“忽略本组”（仅当前会话），避免反复提示。
- 单元测试覆盖分组、保留项、批量移除；UI 截图验收。

**验收**

- 重复组可以一键只保留一首，其余从曲库消失但文件仍在。
- 重新扫描不会自动把已移除的重复项加回来（除非用户重新添加目录）。
- 误操作可通过移除并重新添加该目录恢复。

### v0.13.4 键盘可访问性与焦点系统（M）

**要解决的问题**

- 之前尝试全局焦点环失败，因为缺少显式焦点注册和 Tab 顺序。
- 部分自绘控件只有鼠标可用，AccessKit 名称存在重复。

**工作项**

- 建立轻量焦点注册表：控件 `Id`、顺序、当前焦点。
- 为侧栏、表格行、播放栏、弹窗按钮统一绘制 2px accent 焦点环。
- 明确 Tab / Shift+Tab / Enter / Space / Esc 行为。
- 去掉重复的 AccessKit 名称，给动态控件稳定 ID。
- 增加“键盘快捷键”帮助页。

**验收**

- 仅用键盘可完成：切视图、选歌、播放/暂停、seek、打开设置、关闭弹窗。
- 焦点环在浅色/深色主题都清晰可见。
- AccessKit 自动化能按唯一名称定位主要控件。

### v0.14.0 大曲库与输出设备（L）

**要解决的问题**

- 5 万首以上曲库的搜索、滚动、封面加载缺少量化目标。
- 没有输出设备选择，切换耳机/声卡只能靠系统默认。

**工作项**

- 输出设备枚举与选择，保存设置，设备消失时回退默认。
- 搜索改为去抖 + 预索引；评估 SQLite FTS5。
- 专辑/艺术家视图的封面懒加载和缩略图缓存。
- 性能基准：5 万首曲库启动、搜索、滚动、扫描的耗时记录。
- 只做可测量的优化，不重写 UI 框架。

**验收**

- 5 万首曲库冷启动和搜索达到文档中的目标值。
- 切换输出设备不需要重启。
- 内存占用不随曲库线性增长到不可接受。

## 4. 横切工作

- **测试**：每个版本至少增加解析/存储/播放边界单元测试；UI 改动必须截图检查。
- **稳定名称**：不改中文标签；新增控件必须有 AccessKit 名称和稳定 `Id`。
- **迁移**：新增持久化字段必须有 serde default 和迁移说明。
- **格式化**：不要运行 `cargo fmt --all`，仓库当前不是 rustfmt-clean；只做定向修改。
- **发布**：每次 release 更新 README、`docs/VX.Y_PLAN.md`、`dist/RPlayer/使用说明.txt`，并生成 zip SHA-256。
- **已知限制记录**：歌词 color-key 白边、迷你播放器 DComp、CUE 共享封面等，放入对应版本文档，不静默忽略。

## 5. 暂不做

- 云同步、账号体系、在线流媒体。
- 移动端、macOS/Linux 正式支持。
- 视频播放、DLNA、插件市场。
- 大规模 UI 框架重写；优先在现有 egui 架构内做增量改造。

## 6. 建议执行顺序

1. **v0.13.0 发布工程**：先消除版本不一致，避免后续发布继续带错元数据。
2. **v0.13.1 CUE 回归**：把最近新增的播放逻辑用真实文件压实。
3. **v0.13.2 备份恢复**：在功能继续增长前补上数据安全。
4. **v0.13.3 重复清理**：直接改善日常曲库维护。
5. **v0.13.4 键盘可访问性**：补上长期欠账。
6. **v0.14.0 性能与输出设备**：作为下一阶段的大版本。

## 7. 立即可做的第一件事

先做 **v0.13.0**：把版本号收敛到 `CARGO_PKG_VERSION`，修 `build.rs` 的 `0.12.6.0`，再补发布 checklist。  
这一步风险低、收益直接，也能让后面的每个版本少一次手工同步。
