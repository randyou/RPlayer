# RPlayer v2.0.6 — 验收矩阵与 DPI / 性能基线

基线：v2.0.5（`4613288`，70 tests，exe 2.0.5.0）
目标：把“还有哪些没做完”从口头清单变成可核对的验收资产，并为 DPI 与性能建立可复现的测量方法。

## 1. 范围

本版不重做界面，交付三类验收资产：

1. `docs/qa/v0.2/SURFACE_MATRIX.md`：53 个设计面 + 7 个系统原生面逐项状态、证据、剩余项。
2. DPI 矩阵：100% / 125% / 150% / 200% 与混合显示器，记录 1440×900、1120×720 两种窗口。
3. 性能基线协议：10k 曲库启动、列表滚动、内存、桌面歌词空闲 CPU；本版先固化方法。

## 2. DPI 现状

已实现的保护：

- 窗口最小尺寸 1120×720（逻辑像素），边框自绘，侧/底边原生缩放。
- 所有尺寸走 `src/ui/tokens.rs`，字体走逻辑点，不写死物理像素。
- 1120 宽度下右栏隐藏、顶栏动作折叠、设置弹窗取屏幕可用区域。
- 桌面歌词固定 860×158、迷你播放器固定 410×146，并带尺寸守卫。

本版不修改系统缩放，只记录“当前会话无法覆盖 125% 以上”的事实，避免把未测写成通过。

## 3. 性能基线协议

测试数据：临时库 10,000 首（生成 10k 条最小 WAV 或导入现成目录），封面缓存留空。

记录项：

- 冷启动到首帧：`RPlayer` 进程启动 → 主窗口可交互。
- 曲库首屏：10k 行虚拟列表首屏渲染时间。
- 连续滚动 30 秒：帧时间 P50 / P95，是否出现 >100ms 卡顿。
- 空闲内存：启动 5 分钟后工作集。
- 桌面歌词空闲 CPU：播放暂停、歌词窗口可见 5 分钟的平均 CPU。
- 切歌：上一首/下一首到新封面与歌词出现的时间。

目标值沿用 v2 计划：首帧 < 1.5s、滚动 P95 < 16.7ms、空闲内存 < 250MB、歌词空闲 CPU < 1%。

## 4. 验收

- `SURFACE_MATRIX.md` 覆盖 53 个设计面，状态只能是“已完成 / 部分 / 未验收”。
- 每个“部分/未验收”必须有明确剩余项，不允许空白。
- DPI 表记录实际测试环境；未测项保留“待验收”。
- 性能协议可直接照做，命令、数据规模、记录字段齐全。
- `cargo test --release` 仍为 70 passed；exe metadata `2.0.6.0`。

## 5. 已知限制

- 本版不修复矩阵中的“部分”项，只登记。
- 10k 曲库与 125% 以上缩放未在本会话执行，矩阵中不得标记为通过。
- 系统原生托盘菜单不在自绘范围，仍按系统样式验收。
