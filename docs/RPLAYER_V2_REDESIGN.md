## 1. 设计判断

RPlayer 0.13.5 的功能是完整的：本地扫描、歌词、队列、歌单、多主题、命令面板都在。问题不在功能，在**注意力分配**。

1. **曲目表像数据库。** 七列同时出现评分、格式、收藏、更多；每一列都在说话，于是没有一列被听见。
2. **绿色被当成装饰。** 主按钮、进度条、标签、播放态共用同一个高饱和绿，重点没有层级。
3. **主内容一直在让位。** 常驻右侧栏 + 原生标题栏共同吃掉宽度；窗口缩小时先截断曲名。
4. **六套主题没有形成记忆点。** 都能用，但没有一套让人一眼认出 RPlayer。

设计目标只有一句：**让“正在听什么”成为界面的第一件事，其余信息退后半步。**

---

## 2. 方向：Listening Room / 聆听室

把播放器从“工具面板”变成“一张展开的唱片封套”。

- **底色**：暖纸 `#F4EFE5`，不是纯白；像唱片内页。
- **墨色**：`#1D1B16`，偏暖的黑，长时间看不刺眼。
- **主色**：森林绿 `#2E5B44`，只给主操作、当前播放和少量结构线。
- **信号色**：砖红 `#B64B31`，只给收藏、错误、录制，不做装饰。
- **字体**：标题 Noto Serif SC，界面 Noto Sans SC，元数据 Cascadia Mono。
- **形状**：封面不切圆角；控件 8px、卡片 10px。没有玻璃拟态、没有装饰性渐变。
- **主题**：首版只保留 **Paper（日间）** 与 **Nocturne（夜间）** 两套。

### 为什么收敛主题

六套主题的维护成本不只是六份颜色，还包括六套对比度、六套封面背景、六套截图和六套用户预期。首版用两套把气质做稳，其余保留在代码中作为实验，不出现在设置里。这是本轮最需要审核的产品决策之一。

## 3. 页面与交互

### 3.1 应用框架

| 区域 | 规格 | 说明 |
| --- | --- | --- |
| 侧栏 | 236px | 比当前 252px 更窄；深色，形成纸张与墨的对比 |
| 顶栏 | 54px | 自定义标题栏：面包屑、搜索、离线、主题、设置、窗口控制 |
| 内容区 | 自适应 | 24 / 34px 内边距，页面标题 42px 衬线 |
| 播放条 | 92px | 深色，与侧栏同色；三栏：当前曲 / 传输 / 音量与模式 |
| 右侧栏 | 300px | 只在 ≥ 1280px 显示；窄窗口自动收起 |

自定义标题栏的收益是完整的视觉控制与搜索入口；代价是 Windows 上需要自己处理拖动、双击最大化、边缘缩放和无边框阴影。**这是第二个需要拍板的决策：保留原生标题栏，还是接受自定义标题栏的实现成本。**

### 3.2 本地曲库

- 页面标题“本地曲库”只出现一次，42px 衬线。
- 曲目表从 7 列减到 4 列：`# / 曲目 / 专辑 / 时长`，操作在 hover 或当前行出现。
- 评分与格式不删除数据，只从主表移除；格式变成曲名后的 8px `FLAC` 徽标。
- 行高 56px，缩略封面 38px，曲名 13px，艺术家 9.5px。
- 当前播放行：左侧 2px 森林绿竖线 + 浅绿底 + 四格电平条；不再同时使用高饱和文字和图标。
- 右侧栏只回答三件事：**封面是什么、词在哪、下一首是什么**。其余动作进入“更多”和播放队列。
- 顶部保留搜索，但 `Ctrl K` 是主入口；两者共享查询状态。

### 3.3 专辑

- 5 列封面墙，最后一张是虚线“添加音乐”卡。
- 8 张专辑 + 导入卡在一屏内完整显示，不再出现第二行被播放条裁切。
- 封面上的年份、厂牌是元数据，不抢标题；标题在封面下方，艺术家与年份在同一行。
- 窄窗口降为 4 列 / 3 列，规则由容器宽度决定。

### 3.4 歌单

- 歌单是一张“有封面的小唱片”：封面 156px、标题 40px、总时长与更新时间在标题下方。
- 播放 / 随机是主次两个动作；“更多”收纳导出、重命名、删除。
- 侧栏三张歌单用点数与数量区分，不用文件夹图标。
- 底部固定 `5 TRACKS · 18 MIN` 与“添加曲目 / 导出 M3U”，空白区域因此有明确用途。

### 3.5 正在播放

- 封面最大 430px；标题 `clamp(42, 4.2vw, 60)`，实际 1440 下 60px。
- 歌词 32px，非当前行降为暖灰；当前行只保留一条 14px 短线，不使用彩色高亮块。
- 页面完全隐藏侧栏，只留返回、搜索和窗口控制；播放条左侧变成“沉浸歌词”。
- 背景从封面取色，压到 6% 以内，保证文字对比度 ≥ 7:1。
- 夜间（Nocturne）不是简单反色：保留暖灰墨色与低饱和绿，让封面成为唯一亮面。

### 3.6 命令面板

- `Ctrl K` 打开；输入即筛选曲目、专辑、页面和命令。
- `↑ ↓` 选择，`Enter` 执行，`Esc` 退出；底部常驻快捷键提示。
- 分组固定：跳转 / 曲目 / 操作。每组最多 3 条，避免长列表。
- 选中态使用浅绿底，不使用边框或阴影。

### 3.7 播放队列

- 队列是右侧抽屉，不是第二套页面。
- 顶部“正在播放”卡 + 队列列表 + 底部“队列来源 / 播放模式”三段。
- 当前曲与来源在同一视线内；关闭后回到原页面，不改变播放状态。
- 队列行支持拖动排序（实现阶段再加），首版先保证可读与可关闭。

### 3.8 设置

- 最终信息架构收成 **9 组**：资料库 / 外观 / 播放 / 歌词 / 迷你播放器 / 离线与在线 / 数据 / 快捷键 / 关于。
- 分组按“用户正在调什么”组织，而不是按代码模块；每组最多 7 行，超过则拆组。
- 主题只留两张卡：纸张、夜幕；跟随系统是一个开关。
- 所有设置即时生效，不再有“应用 / 取消”；危险操作必须可撤销。
- 设置窗口 720 × 640；左侧 150px 导航，右侧 36px 行高。主原型目前只展开“外观”页作为视觉样本，最终按 9 组落地。

### 3.9 桌面歌词与迷你播放器

- 迷你播放器固定 410 × 146：封面 92px、曲名、艺术家、进度、上一首/播放/下一首、收藏；左上 5px 森林绿竖条。
- 迷你播放器有两个密度：**标准**（有封面）与**紧凑**（文本优先、居中传输、隐藏封面）；二者共用播放状态与进度。
- 桌面歌词固定 860 × 158：当前行 + 前后各一行，当前行 18–40px 可调；默认无边框、无按钮，悬停才显示锁定 / 设置 / 关闭。
- 歌词面板支持面板不透明度与文字不透明度；锁定后鼠标穿透，双击歌词或托盘菜单解锁。
- 无歌词状态只显示曲名、艺术家和“暂无歌词”，并给出“将同名 .lrc 放在歌曲目录”的可执行路径。
- 两个窗口都不抢主窗口焦点；关闭主窗口时按设置决定是“最小化到托盘”还是“仅隐藏迷你播放器”。

### 3.10 右键菜单

- 只做代码中真实存在的六个：曲目、专辑、艺术家、播放列表、智能歌单、桌面歌词。
- 曲目菜单 15 项按语义分成 5 组：播放 / 收藏 / 评分、加入播放列表、从当前列表移除、歌词与标签、在文件夹中显示、从音乐库移除。
- 危险动作（移除）单独置底，使用信号红，不与常用动作相邻。
- 高分频动作（播放、收藏、评分、加入歌单）在上半区；低频编辑动作在下半区；子菜单延迟 120ms 展开。
- 行高 30px，图标 13px，分隔线 1px；不使用系统默认菜单，统一自绘。

### 3.11 对话框与工具窗口

- 11 个对话框分三类：**创建/编辑**（新建、重命名、编辑标签、批量标签）、**确认**（删除歌单、移除曲目）、**选择/匹配**（重复歌曲、歌词匹配、文件夹、快捷键、关于）。
- 对话框基准 180px 高、480px 宽；标题 12.5px / 说明 8.5px / 正文 9px；底部只保留一个主操作 + 取消。
- 编辑标签与批量标签必须说明“只写入填写字段”，并提示 `tag_backups.jsonl` 可回退。
- 移除曲目必须写明“不会删除文件，下次扫描会重新加入”。
- 四个工具窗口：均衡器（10 段 + 预设 + 前级）、智能歌单（条件 + 实时匹配数）、健康检查（三项指标 + 空态）、歌词编辑器（时间戳行 + 当前行）。
- 工具窗口共用 8px 圆角、36px 行高、同一套开关与滑杆；不与主窗口抢焦点。

### 3.12 浏览与状态

- 补齐艺术家（首字瓦片）、专辑详情（封面 + 曲目）、智能歌单（规则摘要 + 曲目）。
- 空态只说三件事：发生了什么、为什么、下一步做什么；搜索空态给出“清除筛选 / 搜索歌词 / 在文件夹中查找”。
- 多选状态：底部浮出批量条，显示已选数量与总时长，主操作“加入歌单”，危险“移除”单独置右。
- 拖入状态：目标歌单高亮 + 虚线边框 + “松开以添加到「深夜歌单」”，并显示拖入数量与格式。
- 扫描、保存、读取失败各自有独立状态条；错误条必须给出原因与“查看详情”，不能只报“失败”。

## 6. 可访问性

- 正文对比度 ≥ 4.5:1；大标题 ≥ 3:1；暗色主题单独校准。
- 焦点环 2px 森林绿，`outline-offset: -1px`；所有按钮、行、Tab 可键盘到达。
- 曲目行 `Enter / Space` 播放；`F` 收藏；`Q` 队列；`Ctrl K` 命令面板。
- 图标按钮 30–36px，满足 WCAG 2.2 的 24px 最小目标；主要动作 36px。
- 颜色不是唯一状态：当前播放同时有竖线、底色、电平条；收藏有心形填充与 `aria-label` 变化。
- 减少动态效果、跟随系统主题、高对比度三个开关在设置中可见。
- 桌面歌词窗口锁定后鼠标穿透；未锁定时可用键盘移动与关闭。

## 7. 风险与取舍

1. **自定义标题栏**：视觉收益最大，但 Windows 无边框窗口的拖动、缩放、最大化动画和多显示器 DPI 都需要单独验证。若实现成本过高，可退回原生标题栏，保留其余设计。
2. **主题收敛**：会移除四套现有主题入口。需要确认是否有用户依赖；可先隐藏，不删除代码。
3. **右栏自动收起**：1280px 以下隐藏右栏，正在播放信息转移到播放条与“正在播放”页；需要确认窄窗口用户的使用路径。
4. **封面墙**：5 列在 1120px 窗口下会降为 4 列，必须保证不出现横向滚动。
5. **字体体积**：Noto Serif SC / Noto Sans SC 全量字重会增大安装包；实现时按字重子集或系统回退处理。
6. **无边框窗口 + 桌面歌词**：两个独立窗口的置顶、焦点与鼠标穿透需要 Windows 平台验证。
7. **系统托盘自绘**：Win32 托盘菜单的 owner-draw 能做出品牌感，但会失去系统高对比/键盘/多显示器缩放的一部分免费行为；首版建议只做分组、勾选与当前曲头，保留原生菜单。
8. **右键菜单全面自绘**：可统一视觉，但必须补齐键盘导航、屏幕边缘翻转、子菜单延迟与高 DPI；工程量高于主界面。
9. **9 组设置**：比 6 组更完整，但入口更多；首版必须在每组内控制行数，并支持 `Ctrl K` 搜索设置项。

## 8. 审核时需要拍板

1. 是否接受“聆听室”方向：暖纸 + 森林绿 + 衬线标题？
2. 是否同意首版只保留 Paper / Nocturne 两套主题？
