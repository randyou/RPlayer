# RPlayer Bug Log

## BUG-005 · 桌面歌词控件透明度与 0% 边框

| 字段 | 内容 |
| --- | --- |
| 状态 | Fixed（0% 边框仍需实机确认） |
| 严重度 | Medium |
| 版本 | v0.7.1 |

### 修复

- 齿轮与关闭按钮透明度统一跟随面板不透明度：面板 0% 时两者也隐藏，面板 85% 时同为 85%。
- 去除窗口区域（`SetWindowRgn`）造成的深色 1px 内框。
- 关闭 DWM 边框颜色和 `DWMNCRP_DISABLED`，并尝试用内缩区域遮住最外 1px。
- 0% 颜色键背景向外扩 16px 绘制，避免矩形抗锯齿边留下深色描边。
- 面板 0% 时不再绘制任何面板描边。

### 已知

- 在某些 Windows 11 合成状态下，窗口阴影仍可能出现一条极淡的顶部线，需实机确认是否仍可见。

## BUG-003 · 桌面歌词面板 0% 时显示黑色

| 字段 | 内容 |
| --- | --- |
| 状态 | Fixed |
| 严重度 | High |
| 发现时间 | 2026-11-24 03:20 (Asia/Shanghai) |
| 版本 | v0.7.1 |
| 平台 | Windows 11 |

### 原因

- `storage.rs` 加载时把 `desktop_lyrics_opacity` 强制夹到 `0.35`，用户设置 0% 实际不会生效。
- 该 GL 渲染器的透明窗口不保留逐像素 alpha；面板透明区域被合成成黑色。

### 修复

- 存储迁移允许 0.0–1.0。
- 面板为 0% 时切换 Windows 颜色键透明（`LWA_COLORKEY`），背景使用专用键色，歌词文字保持不透明。
- 面板 >0% 时恢复普通窗口合成。

### 验证

- 面板 0% 时桌面可见，不再出现黑色面板。
- 歌词文字保持可见。

## BUG-002 · 托盘菜单点击无反应

| 字段 | 内容 |
| --- | --- |
| 状态 | Fixed（待系统托盘菜单人工复验） |
| 严重度 | High |
| 发现时间 | 2026-11-24 02:25 (Asia/Shanghai) |
| 版本 | v0.6.0 |
| 平台 | Windows 11 |

### 复现步骤

1. 启动 RPlayer，点击关闭按钮隐藏/最小化到托盘。
2. 右键托盘图标打开菜单。
3. 点击「显示主窗口」「播放 / 暂停」「设置」或「退出」。

### 实际结果

菜单项点击后没有任何反应。

### 原因

托盘菜单事件只在 `RPlayerApp::poll_tray` 中轮询，而该函数只在 eframe 的 `update` 中调用。主窗口隐藏/最小化后，eframe 停止更新，菜单事件排队但永远不被消费。实测隐藏后轮询计数只停在 `poll 0`。

### 修复

- 移除 `tray-icon` / `muda` 菜单实现，改为原生 Win32：
  - `Shell_NotifyIconW` 注册托盘图标；
  - 独立线程 + message-only/隐藏窗口消息循环；
  - `CreatePopupMenu` + `TrackPopupMenu` 显示原生菜单；
  - 菜单项直接通过 ID 分发，不再依赖 `MenuEvent` 回调。
- 菜单动作写入独立队列。
- 收到动作后通过 Win32 `ShowWindow(SW_RESTORE)` / `SetForegroundWindow` 恢复主窗口，唤醒 eframe 再消费队列。
- 关闭到托盘使用最小化窗口，而不是 `Visible(false)`。
- 主窗口保留 250ms 重绘心跳。
- 已删除 `tray-icon` 依赖。

### 验证

- Release 构建通过；24 个单元测试通过。
- 原生图标成功注册，`Shell_NotifyIconGetRect` 返回有效坐标。
- 自动化环境会把托盘图标放进 Windows 溢出区，且存在旧图标/闪烁问题，无法可靠地用合成鼠标点中菜单项；**需要用户在真实桌面点击菜单复验**。
- 菜单本身由 Windows 原生 `TrackPopupMenu` 绘制，不再经过第三方菜单事件通道。

## BUG-001 · 设置窗口顶部超出屏幕，无法关闭

| 字段 | 内容 |
| --- | --- |
| 状态 | Fixed |
| 严重度 | High |
| 发现时间 | 2026-11-24 01:42 (Asia/Shanghai) |
| 版本 | v0.6.0（`1be4a42`） |
| 平台 | Windows 11 |
| 截图 | 原始 [bug-settings-close.png](bug-settings-close.png) · 修复后 [bug-settings-close-fixed.png](bug-settings-close-fixed.png) |

### 复现步骤

1. 启动 RPlayer。
2. 点击顶栏右侧齿轮按钮打开设置。
3. 查看「外观」中的主题选项。
4. 尝试点击右上角关闭按钮。

### 实际结果

- 设置窗口顶部超出主窗口/屏幕可见区域。
- 顶部标题、关闭按钮（右上角 X）完全不可见。
- 设置面板底部也没有「关闭」按钮。
- 按下 `Esc` 不会关闭设置。
- 用户无法通过界面退出设置，只能关闭整个应用。

### 期望结果

- 设置窗口始终完整位于屏幕可见区域内。
- 右上角关闭按钮始终可见、可点击。
- `Esc` 可关闭设置。
- 内容过高时内部滚动，而不是把头部推出屏幕。

### 原因

`src/app/settings.rs` 原使用固定尺寸：

```rust
.anchor(Align2::CENTER_CENTER, Vec2::ZERO)
.fixed_size(Vec2::new(470.0, 640.0))
```

加上外层 `inner_margin(22)` 后实际占用高度约 684 逻辑点。在高 DPI / 较矮窗口下，居中锚定会把窗口顶部推到负坐标，头部（含关闭按钮）被裁剪到屏幕外；设置窗口也没有滚动区或 `Esc` 兜底。

### 修复

- 设置窗口高度改为按 `ctx.screen_rect()` 自适应：
  - 高度限制为 240–640 逻辑点；
  - 宽度限制为 320–470。
- 内容放入垂直 `ScrollArea`，头部和关闭按钮固定在滚动区外。
- 增加底部「完成」按钮。
- 增加 `Esc` 关闭设置。
- 修复后实机验证：
  - 设置头部与右上角关闭按钮可见；
  - 点击关闭按钮可退出；
  - 重新打开后按 `Esc` 可退出。

### 原临时绕过

- 用主窗口标题栏关闭整个 RPlayer（开启托盘时进程会继续驻留）。
- 临时降低 Windows 显示缩放，或增大应用窗口高度后重新打开设置。
- 应用内没有可靠的关闭设置方式。
