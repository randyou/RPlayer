## 6. 建议顺序与体量

1. **第 1 周**：A1 → A2 → A3（v2.1.0 发版），约 5–6 人日。
2. **第 2 周**：B1（紧凑布局，含 200% 实机）→ B2 → B3，约 5 人日；顺带 D2/D3。
3. **第 3–4 周**：C1 → C5 → C3 → C2 → C4，约 10–14 人日（v2.2.0）。
4. 之后：C6、B4/B5、D1 作为维护项穿插。

合计约 **20–25 人日**（不含真机 DPI 硬件等待时间）。按单人节奏约 4–5 周；若只求「v2.1.0 可发布」，**5–6 人日**即可收口。

## 7. 与 v2 目标的差距判断

- **功能面**：v2 的承诺（本地优先、离线可用、桌面歌词、智能歌单、CUE、备份恢复）已闭环，53 面矩阵已收口，没有未验收的设计面。
- **质量面**：还差三项硬指标 —— 滚动 P95、空闲 CPU、真机 DPI；其中滚动与 CPU 是「同一类问题」（每帧成本 + 唤醒频率），一起做最省事。
- **规模面**：10k 可用，5 万首与输出设备仍属于 v2.2.0 范围，不阻塞 v2.1.0 发布。
