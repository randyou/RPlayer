# RPlayer v2.0.17 — 桌面歌词残留定案 / 多选操作条 / 矩阵收口

日期：2026-11-25

## 范围

1. **桌面歌词切歌残留（GAP 06）定案**
   - 结论：v2.0.16 不能复现。旧观察来自仍在运行的 v2.0.14 进程（PID 23996，覆盖层数小时不变），
     且 `v2012-lyrics-stale.png` 的淡色文字是 `panel_alpha = 0.78` 的 DComp 面板透出主窗口内容。
   - 防御性硬化：`sync_overlay` 改为返回“内容是否变化”，变化时显式
     `request_repaint_of(lyrics_viewport / mini_viewport)`；`overlay_content_key` 只哈希可见字段
     （不含 position，避免每帧都判定为变化）。
2. **DComp 面板命中区**
   - `WM_NCHITTEST` 过去恒返回 `HTCLIENT`，整个 860×158 矩形都吃掉点击。
   - 改为按 18px 圆角胶囊判定：胶囊内 `HTCLIENT`，胶囊外 `HTTRANSPARENT`；`WM_LBUTTONDOWN` 同步拦截。
3. **多选操作条（GAP 09）0 / 3 / 24 三态**
   - 38px 单行；`BatchBarMode::Empty / Small / Large`，阈值 `BATCH_LARGE_THRESHOLD = 20`。
   - Empty：只提示“Ctrl 点选 · Shift 范围选择”，右侧只留“全选当前结果 / 退出批量”。
   - Small：`加入歌单`（下拉：已有歌单 + 新建播放列表…）、`加入队列`、`编辑标签…`（仅播放列表/收藏显示`移除选中`）、`全选当前结果`、`清空`、`退出批量`。
   - Large（≥20）：只留 `清空全部 / 退出批量`，避免误触批量破坏性操作。
   - 跨视图：`switch_view` 不再清空 `batch_mode` / `checked`，切走后条上显示“另有 N 首不在当前视图”。
   - 重复加入同一歌单不再显示“已添加 0 首”，改为“这 N 首已在「X」中”。
4. **矩阵收口**
   - 标题栏顶边缩放正式记为“按设计不适用”（顶边只拖动，侧/底用 `SetWindowPos` 缩放）。
   - 多选操作条、桌面歌词·无歌词两面改为 `已完成`，证据 `v2017-*.png`。
