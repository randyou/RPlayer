# v0.13.2 · 数据备份与恢复

主题：在曲库功能继续增长前，给用户一个可移动、可验证、可回滚的数据备份入口。

## 目标

- 设置页可以一键备份曲库状态到任意文件夹。
- 恢复前自动备份当前数据；备份损坏时不覆盖现有数据。
- 支持只恢复设置与播放列表，避免换机后音频路径冲突。
- 恢复后立即刷新界面，不用重启。

## 备份包结构

```
RPlayer-backup-<毫秒时间戳>/
  manifest.json
  library.json
  library.db
  playback_stats.json
  session.json
  covers/            # 可选
  lyrics/            # 可选
  lyrics_custom/     # 可选
```

`manifest.json` 记录应用名、备份 schema、RPlayer 版本、创建时间、是否包含媒体以及文件清单。

## 实现

- `src/backup.rs`
  - `create(data, dest_parent, include_media)`：创建备份目录，复制核心文件；SQLite 用 `VACUUM INTO` 生成一致快照。
  - `inspect(dir)`：校验 manifest、`library.json`、SQLite `integrity_check` 与 `tracks` 表、统计/会话 JSON、媒体目录。
  - `restore(data, backup, settings_only)`：先创建恢复前快照，再应用；失败自动回滚。
  - 媒体目录递归复制；恢复数据库后清理旧的 `-wal`/`-shm`。
- `src/app/settings.rs`
  - 新增「数据」卡片：备份、恢复、包含媒体、只恢复设置。
  - 恢复前用系统确认框说明影响范围。
  - 恢复后重载曲库、主题、统计、音量、EQ 与 ReplayGain 设置。

## 验收

- 备份目录包含 manifest 和四个核心文件；勾选媒体时包含 `covers/`、`lyrics/`、`lyrics_custom/`。
- 损坏 `library.json` 或 SQLite 的备份会被拒绝，现有数据不变。
- 完整恢复后曲目数、歌单、收藏、设置与统计一致。
- 只恢复设置时，当前曲库与统计保持不变。
- 每次恢复都会在 `%APPDATA%\RPlayer\backups` 留下恢复前快照。
- 单元测试覆盖创建/检查/完整恢复/仅设置恢复/损坏拒绝/媒体开关；`cargo test --release` 通过。
- UI 验收：设置页「数据」卡片在滚动区域内完整可见，按钮与说明不重叠。

## 已知边界

- 备份不包含音频文件本身，只包含曲库索引与设置。
- 恢复媒体缓存是合并写入，不删除目标目录里已有的额外文件。
- 备份包是普通文件夹，不加密；分享前应确认其中不含隐私路径或歌词。
