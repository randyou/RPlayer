# v0.13.3 · 重复歌曲清理

主题：把 v0.12.0 的重复歌曲“只读列表”变成可逐组处理、可恢复的曲库维护工具。

## 目标

- 重复组内可逐首查看完整信息并定位文件。
- 一键只保留其中一首，其余只从曲库移除，不删除磁盘文件。
- 移除后重新扫描不会自动加回；重新添加目录可恢复。
- 支持仅本次运行忽略某组，避免反复提示。

## 实现

- `src/model.rs`
  - `Library.ignored_tracks: Vec<String>`，serde 默认空；保存被移除曲目的 `scan_key`。
  - Library schema 6。
- `src/duplicates.rs`
  - `others(group, keep)` 返回除保留项外的 id。
  - `signature(ids)` 生成与顺序无关的组签名，用于会话内忽略。
- `src/app/mod.rs`
  - `keep_duplicate_track` 二次确认后移除记录、写入 `ignored_tracks`，并清理歌单、队列与勾选。
  - 扫描已知集合改用 `scan_key`，删除后重新扫描仍能命中忽略表。
  - `remove_folder` 清理该目录下的忽略键，因此重新添加目录会恢复这些歌曲。
  - `reveal_path` 在资源管理器中选中文件。
- `src/app/dialogs.rs`
  - 每行展示艺术家、专辑、格式、时长和路径。
  - 操作：「定位」「仅保留此首」；组头「忽略本组」。
  - 保留按钮的无障碍名称包含标题与路径，避免同名按钮无法自动定位。

## 验收

- 两个同标签、同时长的文件会进入同一重复组。
- 保留原文件后，曲库从 9 首变 8 首，磁盘副本仍存在。
- 重新扫描后仍为 8 首，不自动加回被移除项。
- 移除并重新添加测试目录后恢复为 9 首，证明忽略键已清理。
- 对话框、工具栏入口和确认提示在浅色主题下布局正常。
- `cargo test --release`：54 passed。

## 已知边界

- 判断依据仍是同名、同艺术家、时长差 ≤2 秒；不同版本/现场版可能误判，需人工确认。
- 「忽略本组」仅当前运行有效，不写入设置。
- 移除操作不写入“最近删除”，恢复依赖重新扫描或重新添加目录。
