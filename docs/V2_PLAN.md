## 0. 结论先行

设计稿补齐后，v2 的剩余工作从“猜着做”变成“对稿做”，重心整体后移一版：

- **v2.1.0 立即发版**：只做回归与发版（A5/A6）。**不再往里塞对稿改动**——现有实现与稿件的差异登记成清单，进入 v2.2.0。
- **v2.2.0 变成“按稿对齐版”**：托盘、迷你播放器、品牌落地、5 个工具对话框、响应式骨架、歌词阴影，共 9 个包，约 **15–22 人日**。
- **v2.3.0 才是规模化**：输出设备、搜索索引、封面懒加载、5 万首基准、导入吞吐、CUE 多 FILE。

也就是说：**v2 距离“完成”还剩约 20–28 人日**，其中 15–22 天是“把已经能用的界面按稿重做”，不是新功能。

## 2. v2.2.0 按稿对齐（P0，15–22 人日）

每项交付：实现 + 浅/深（必要时 8 态）截图 `docs/qa/v0.2/v220-<面>-<态>.png` + 矩阵对应行改「按稿完成」。

### S1 托盘 D1–D4（S，1–2 天）

对照 `spec2-tray.png`，现有自绘弹窗已接近，差的都是细节：

- 圆角 10 → **8**；抬头 62 → **58**，并在抬头下加 **2px 只读进度条**（当前无）。
- 分隔线：现状 3 条 → 稿为 **2 条**（三组：窗口与传输 / 收藏与浮层 / 设置与退出），`设置` 与 `退出` 之间不再分隔。
- 禁用态：传输四行 + 收藏在无曲目时 **35% 不透明度**且仍占行高（现为 faint 文字色，视觉不一致）。
- 勾选标记 12px；`退出 RPlayer` 永远最后一行、signal 红。
- 动效：现为 120ms 从图标缩放 → 稿为 **140ms opacity + 2px 上移**（不回弹、不 stagger）。
- 托盘图标换成 Sleeve R（16/24/32，不随播放状态换脸）；悬停提示三态：`RPlayer · 正在播放 / 一千年以后 — 林俊杰`、`RPlayer · 已暂停`、`RPlayer · 未在播放`，延迟 500ms、不换行。
- 点击语义：单击显示并聚焦、**双击播放/暂停**（当前双击也是显示）、右键菜单、中键无动作。

### S2 迷你播放器 D15（S，1–2 天）

- **去掉内部强制 Forest**（`show_mini` 现在每帧 `set_preset(Forest)` 再还原）→ 跟随应用主题，出**浅/深 × 经典/紧凑 × 有/无封面** 8 态。
- 上一首/下一首图标 26 → **20px**；顶部 4×24 动作**仅 hover 显示**（现在常显）。
- 空标题兜底 `未命名曲目`（副行已有 `未知艺术家`）；**紧凑态永不显示封面位**（现仍占位）。
- 动效：窗口进入 280ms 淡入 + 4px 上移（现无）；播放按钮 press 90ms `scale 0.975`；拖动中 1px 虚线 accent + 阴影。
- 校对：圆角 16 / 封面 92 / 内边距 13 / 标题 14.5·600·max 250 已对齐，不再动。

### S3 品牌落地（S，1 天）

- `design/rplayer-v2/brand/` 的 SVG 光栅化进 `assets/`：窗口图标 `.ico`（16/24/32/48/256）、关于页 44px、标题栏 mark（Nocturne 用 reversed）。
- 规则校验：最小 16px、留白 `x = 1/4 标识宽`、16–24px 不描边、深底反白、signal 红不进标识。
- `favicon-32.png`、`og-1200x630.png` 归档进 `docs/brand/` 供 README 引用（应用本身不需要）。
- 现有 `RPlayer` 字标是自绘文本，改为按稿用 Noto Serif SC 600 的光栅图或按同一字重绘制，并在字体缺失时回退（不嵌字体）。

### S4 曲库工具 D5–D6（M，2–3 天）

- **健康检查 720×340**：66px 抬头、三张数字卡（缺失文件 / 空标签 / 重复候选，数字 30 serif）、44px 问题行（图标 + 文案 + 单一动作）、空态绿勾 + `没有发现明显问题`、底部 `重新检查`；扫描中显示 `1,240 / 2,018 首 · 可继续播放` + 进度条；目录不可读时 `跳过该目录，其余曲库继续扫描`。
- **重复歌曲 720×340**：组头 `龙卷风 — 周杰伦` + `1 组 / 2 个文件`；每行 FLAC 保留 / MP3 忽略、高亮行左侧 2px accent、行内 `仅保留此首` / `定位`；底部危险动作 `删除 1 个重复项` 独立右侧，`忽略本组 / 取消` 退描边。

### S5 编辑类对话框 D7–D9（M，3–4 天）

- **歌词编辑 820×430**：行高 36、时间列 58/82、当前行 accent-soft + 2px 左条、播放/删除 22×22、底部固定 `取消 / 保存歌词`、`未保存` 标记；非法时间只标红该行不弹窗。
- **智能歌单 620×430**：条件行三段 116 / 88 / flex，行高 34；空值行红框 + 底部一条 `第 3 条规则缺少值`、保存禁用；实时 `0 首匹配`；>5 行滚动不压行高。
- **均衡器 820×250**：10 段竖推子 62px 间距、预设单行横向滚动不折行、前级 +0.0 dB、重置；即时生效不写文件。现为 548×404 浮窗，尺寸与密度都要改。

### S6 系统面 D10–D12（M，2–3 天）

- **快捷键 820×460**：21 条两栏 10/11、行高 26、按键列 88px、分组 `全局 / 播放 / 列表与选择 / 焦点`；底部说明可重绑、冲突以后设置者为准。注意稿里的矛盾点：`焦点内 Space 激活控件` 要写进说明并核对现有 `handle_shortcuts` 的 `wants_keyboard_input` 守卫。
- **关于 380×280**：44px 标识、`RPlayer` / `v2.x · 本地优先`、数据目录、开源许可、构建；**不做检查更新**。
- **拖入 380×220**：目标行 1px 虚线 accent + accent-soft 底、右侧 `+3` 徽标 + `松开以添加`、底部“拖到任意歌单行即可添加 · 不改变当前播放队列”；不改变行高、不显示全屏遮罩。
- **错误详情 D12 内联展开**：标题 + 一行原因 + `路径 / 错误码 / 时间` + `诊断`（`os error 32 · 文件被占用 · 已重试 2 次`）+ `在文件夹中显示 / 复制诊断信息 / 重试`；展开 280ms，只推下方内容。

### S7 响应式骨架 D13（L，4–6 天）

这是本版最大的一块，也是 200% DPI 破版的根治：

- 断点：`≥1280` 236 侧栏 + 300 右栏；`1120–1279` 隐藏右栏；`840–1119` 侧栏收 72 图标 + 表隐藏专辑列 + 播放条 76；`<840` 侧栏抽屉化 + 播放条两行 96 + 对话框 `min(92vw, 720px)`。
- 最小逻辑宽 720，不再承诺 1120 以下完整布局；`src/main.rs` 的 `with_min_inner_size([1120,720])` 要随断点放开。
- 抽屉 280ms；断点切换**不播动画直接重排**（避免 resize 抖动）。
- 验收：1024×720、720×720（=1080p@200% 实机）两张稿逐项对；再补 125/150/200% 真机截图。

### S8 桌面歌词 D14（S，0.5 天）

- 接受 1px color-key 白边（不换分层窗口路径），改为文字阴影：浅壁纸 `0 0 1px rgba(0,0,0,.35)`、深壁纸 `0 0 1px rgba(255,255,255,.22)`，只阴影不描边不加底色。
- 验收：50% 灰 / 纸色 / 浅绿照片三种壁纸上当前行对比度 ≥ 4.5:1、白边 ≤1px。
- 设置·桌面歌词页加一句人话说明（不暴露技术术语）。

### S9 可访问性补齐（S，1–2 天）

## 6. 风险与取舍

- **S7 是最可能超期的一项**：响应式会牵动 `library_view`、`sidebar`、`player_bar`、`topbar` 五处布局常量，且有 4 个断点 × 浅/深两态。建议先做 840–1119 与 <840 两个“现在完全没有”的档，再做 1120–1279 的隐藏右栏。
- **S5 的均衡器尺寸变化会改音频 UI 的视觉重心**（548×404 → 820×250），现有推子绘制是按 404 高排的，重排比改配色贵。
- **S2 去掉 Forest 强制后**，迷你播放器会出现“浅色桌面上的浅色小窗”，需要顺带确认与主窗纸张主题的对比度，不要出现边界看不清。
- **回归口径**：矩阵保留“功能已通 / 按稿完成”两列，不把 v2.1.0 的 53 面重新打回未完成——否则 v2.1.0 永远发不出去。
- **稿与实现的已知冲突**：稿 D1 写“当前 `TrackPopupMenu` 为原生菜单”（已过时，我们已是自绘），按自绘实现；稿 D1 的 `Space` 在托盘菜单里无意义（菜单不吃键盘），实现时不显示该快捷键。
