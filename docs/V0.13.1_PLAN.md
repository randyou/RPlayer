# v0.13.1 · CUE 真实回归

## 目标

用真实时长的音频验证 CUE 虚拟曲目，而不是只验证时间换算函数。重点覆盖起点、终点、单曲时长、自动切歌边界和真实文件路径。

本版本不扩展 CUE 功能，只把已有承诺测扎实，并让不支持的 CUE 明确失败。

## 背景

- v0.12.1–v0.12.3 的 CUE 测试夹具只有约 2.3 毫秒，所有虚拟曲目时长都被压到 0.05 秒，无法发现时长或边界错误。
- v0.12.9 修复了 CUE 分段播放，但缺少“扫描出真实曲目后再检查播放映射”的端到端测试。
- 多 `FILE` 的 CUE 会把所有曲目错误地挂到最后一个文件上；应显式拒绝。
- `INDEX 00` 是前置间隙，曲目应从 `INDEX 01` 开始。

## 实现

1. **真实时长夹具**
   - `write_wav(path, seconds)` 生成 44.1kHz 单声道 WAV。
   - CUE 回归使用 12 秒音频、三首曲目，起点分别为 0、5、10 秒。

2. **端到端断言**
   - 三首虚拟曲目的 `duration`、`cue_start`、`cue_end`。
   - `playback::start` 从 CUE 起点开始。
   - `absolute` / `relative` 在单曲区间内正确换算。
   - `reached_end` 在本曲终点前触发，下一首之前不提前触发。

3. **解析健壮性**
   - 明确忽略 `INDEX 00`，只使用 `INDEX 01`。
   - 多 `FILE` 返回“暂不支持包含多个 FILE 的 CUE”。
   - 音频文件名含空格和中文时仍能解析到真实文件。

4. **会话恢复迁移**
   - 新增 `playback::resume(track, saved, schema)`。
   - schema < 2 的 CUE 会话把整轨绝对位置换算成单曲相对位置。
   - schema 2 直接使用单曲相对位置，普通曲目不受影响。

## 验收

- [x] `cargo test --release`：46 passed。
- [x] CUE 三首曲目的时长分别为 5、5、2 秒。
- [x] 第二首从 5 秒开始，在 10 秒结束。
- [x] `INDEX 00` 不会把曲目起点提前到 0。
- [x] 多 `FILE` CUE 被拒绝并给出明确错误。
- [x] 含空格/中文文件名的 CUE 能扫描出曲目。
- [x] 旧 CUE 会话位置迁移到单曲区间。
- [x] release 构建通过。
- [x] 便携包重新生成并记录 SHA-256。

## 已知限制

- 含多个 `FILE` 的 CUE 仍不支持；现在会明确报错，而不是播放错误的音频。
- CUE 曲目仍与整轨共享封面和歌词。
- 没有可自动操作的真实 CUE 专辑用于 UI 点击回归；播放链路由扫描测试和 `playback` 单元测试覆盖。

## 风险

- 测试夹具从 2.3 毫秒改为 12 秒，临时目录占用约 1MB/用例；测试结束会删除。
- 不运行 `cargo fmt --all`，避免整树格式化 diff。
