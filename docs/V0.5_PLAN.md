## 1. 为什么是这一版

RPlayer v0.4 已经有按 `F` 打开的全屏“正在播放”页，也有大封面、逐行歌词、桌面歌词和迷你播放器。但从用户视角看，仍有两个明显问题：

1. **播放页不像“播放器主页”**：侧栏没有“正在播放”入口，底栏入口也不明显；歌词不能点击跳转，封面不能更换，播放页与曲库/歌词/封面之间缺少联动。用户很容易认为“没有播放界面”。
2. **封面只能靠内嵌图**：没有 `folder.jpg` / `cover.jpg` 回退，也没有在线匹配；大量 WAV、老 MP3、独立音乐只能看到占位图。

同时，按 [REQUIREMENTS.md](REQUIREMENTS.md) 的 P0 审计，RPlayer 还缺：

- 无缝播放；
- 播放会话恢复；
- 队列持久化/排序；
- Windows 系统媒体控制（SMTC）/媒体键；
- 文件夹监听；
- 在线封面与封面缓存。

v0.5 的目标不是“再加一堆设置”，而是把 **“打开播放器 → 看到正在播放 → 有封面和歌词 → 连续听下去 → 系统能控制”** 这条主链路做完整。

## 2. 版本目标与边界

### 2.1 目标

- 用户从侧栏、底栏或快捷键都能进入“正在播放”，并把它当作播放器主页面。
- 没有内嵌封面的歌曲，能自动匹配到网络封面并缓存；匹配不到时有明确兜底。
- 专辑/现场曲目连续播放无可感知间隙。
- 关闭/重启后恢复上次歌曲、进度、队列。
- Windows 任务栏/锁屏/耳机媒体键可以控制播放。
- 新增/删除/改名音乐文件后，曲库自动更新。

### 2.2 非目标（本版不做）

- ReplayGain、M3U 导入导出、单实例/文件关联、歌词时间轴偏移 → 放到 **v0.5.1**。
- 评分、播放次数、智能歌单、标签编辑、专辑/艺术家网格 → **v0.6**。
- 输出设备选择、WASAPI 独占、交叉淡化、变速、可视化 → **v0.7**。
- 在线音乐、播客、DLNA、Last.fm、插件市场 → 不在当前路线。
- 不抓取商业音乐平台封面；不使用不允许缓存的商业 API。

### 2.3 成功标准（版本级）

| 指标 | 目标 |
| --- | --- |
| 播放页入口 | 侧栏/底栏/`F` 三处均可进入；用户 3 秒内能找到 |
| 封面覆盖率 | 测试曲库中 ≥80% 的播放曲目有封面（内嵌/本地/在线任一） |
| 在线封面时延 | 有网络时 ≤3s 出现；≤8s 失败并显示兜底 |
| 无缝间隙 | 测试专辑可感知间隙 0 次；≤50ms |
| 会话恢复 | 重启恢复上次曲目/进度/队列 ≥99% |
| 系统控制 | 播放/暂停/上下曲在 SMTC/媒体键全部可用 |
| 曲库新鲜度 | 文件夹变化 ≤5s 反映到 UI |
| 稳定性 | 无因封面/歌词网络失败导致的崩溃或卡死 |

## 4. 关键体验设计

### 4.1 正在播放页布局

目标窗口：1200×780；最小 940×640。

```text
┌──────────────────────────────────────────────────────────────┐
│ 收起   正在播放 · RPlayer       [封面] [歌词] [队列] [设置]  │
├────────────────────────────┬─────────────────────────────────┤
│                            │  歌词（主内容，居中滚动）        │
│      大封面（约 360）       │                                 │
│                            │  上一行（淡）                    │
│  歌名 / 艺术家 / 专辑       │  当前行（强调色，24–28px）       │
│  格式/时长/封面来源徽标      │  下一行（淡）                    │
│                            │                                 │
│  ♥ 收藏   ⇩ 歌词   ⟳ 封面   │  歌词来源：LRCLIB / 本地 / 无    │
│                            │  偏移：−0.5s  0  +0.5s           │
├────────────────────────────┴─────────────────────────────────┤
│ 00:42  ●──────────────────────────────────────────  03:48    │
│        ⏮   ▶/⏸   ⏭      🔀  🔁  🔊  ▣ 队列                 │
└──────────────────────────────────────────────────────────────┘
```

要点：

- **侧栏新增“正在播放”**：显示当前曲目缩略图、歌名、播放状态；无当前曲时置灰或显示“未在播放”。
- **底栏封面/标题可点击**进入播放页，保留右上角展开按钮与 `F`。
- **默认不强制跳转**：双击播放仍在曲库；用户可通过入口进入播放页。首次使用可在底栏给一次轻提示“按 F 查看正在播放”，不弹窗。
- **歌词为主**：右侧歌词区宽度 ≥50%，当前行垂直居中；点击任意行 seek 到该行时间。
- **队列抽屉**：右侧可展开，不遮挡歌词；小窗口时默认关闭。
- **无歌词**：显示“未找到歌词”，提供“从 LRCLIB 搜索”“选择本地 .lrc”；不显示空白大块。
- **无封面**：占位图 + “自动匹配中…”或“未找到封面 / 重新匹配 / 选择本地图片”。
- **封面来源徽标**：内嵌 / 本地 / 网络 / 缓存；点击可看来源说明。
- **氛围背景**：从封面提取主色/模糊作为背景；无封面用主题渐变；切换曲目 200–300ms 过渡。

### 4.2 歌词交互

- 当前行高亮，前后行降级；远离当前行的歌词淡出。
- 自动滚动以当前行为中心，避免每帧抖动；用户手动滚动后暂停自动跟随 2–3 秒。
- 点击歌词行：seek 到该行时间并继续播放。
- 纯文本歌词：显示全文，不强行高亮；提示“无时间轴”。
- 歌词来源状态：本地 `.lrc` / 内嵌 / LRCLIB / 缓存 / 无。
- 下载中：显示“正在搜索歌词…”；失败给可重试提示。
- 偏移（P1）：±5s，0.5s 步进，按曲目保存；桌面歌词同步。

### 4.3 在线封面自动匹配

#### 优先级

1. 音频内嵌封面（lofty）。
2. 同目录 `cover.jpg` / `folder.jpg` / `front.jpg` / `album.jpg`（png 同样支持，大小写不敏感）。
3. RPlayer 封面缓存。
4. 在线匹配（仅当开启自动匹配）。
5. 占位图。

#### 在线来源

- **MusicBrainz**：按艺术家/专辑/曲名搜索 Release Group，获取 MBID。
- **Cover Art Archive**：`/release-group/{mbid}/front-500`，失败可回退 `/front` 原图，客户端缩放/压缩到 ≤1200px。
- 不使用 iTunes Search API 作为封面源：Apple 条款把封面限定在带商店徽章/推广语境的页面，不适合本地播放器缓存与长期展示。
- 不抓取 QQ 音乐/网易云/酷狗等商业平台封面。

#### 匹配策略

1. 归一化艺术家、专辑、标题（大小写、全半角、括号版本标记）。
2. 优先 `primary-type=Album`，排除现场/合辑/翻唱（除非用户原专辑就是）。
3. 用曲目时长、专辑年份、曲目数做辅助评分。
4. 高于阈值才自动应用；低于阈值标记“待确认”（P1 显示候选），不静默用错图。
5. 专辑级缓存：同一艺术家+专辑只查一次；不同曲目共享。
6. 负缓存：未命中记录 30 天，避免每次播放都请求；手动“重新匹配”可忽略负缓存。
7. MusicBrainz 请求串行，遵守 **平均 1 请求/秒** 与可联系 `User-Agent`；429/503 退避。
8. 网络超时 15s；封面下载 20s；大小上限 5MB；图片解码失败回退占位。

#### 缓存

- 目录：`%APPDATA%\RPlayer\covers/`。
- 文件：按专辑 key 的哈希命名，例如 `covers/<hash>.jpg`；索引 `covers/index.json` 记录 artist/album/MBID/source/updated_at。
- 负缓存：`covers/index.json` 中 `status=miss` + `expires_at`。
- 设置页显示缓存大小/清除按钮。
- 不把网络封面写回音乐文件夹（避免修改用户文件）；用户手动“设为本地封面”才可选另存。

#### 合规与隐私

- 设置中说明：自动匹配会把艺术家/专辑/曲名发送给 MusicBrainz；可在设置关闭。
- Cover Art Archive 图片版权归原权利人/上传者；RPlayer 仅缓存用于本地展示，不随安装包分发、不提供封面导出市场。
- UI 标注“封面来自 Cover Art Archive”，并提供项目主页链接。

## 5. 技术方案（概要）

### 5.1 新增模块

| 模块 | 责任 |
| --- | --- |
| `src/cover.rs` | 封面来源枚举、缓存 key、本地 sidecar 查找、图片解码/缩放 |
| `src/cover_fetch.rs` | MusicBrainz 搜索、Cover Art Archive 下载、匹配评分、限速与错误分类 |
| `src/app/cover_worker.rs`（或并入 mod） | 后台请求队列、事件通道、去重/取消 |
| `src/app/session.rs` | 播放会话 JSON 的保存/恢复 |
| `src/watch.rs` | 文件夹监听、防抖、增量事件 |
| `src/platform/media.rs` | Windows SMTC 适配（可先用 `windows` crate/COM） |

> 具体文件划分可在实现时调整；原则是网络/文件 IO 不进 UI 帧。

### 5.2 数据流

```text
播放歌曲
  → 本地封面解析（内嵌/sidecar）
  → 命中：立即显示
  → 未命中：查封面缓存
      → 命中：显示
      → 未命中且自动匹配开启：入队后台任务
          → 查 MusicBrainz（1 req/s）
          → 有 MBID：下载 CAA 封面
          → 成功：写缓存 → 通知 UI → 显示
          → 失败/无结果：负缓存 → 占位图 + 手动重试
```

- 每个专辑 key 同时只允许一个 in-flight 请求。
- 切歌不取消正在下载的封面（完成后入缓存，下一次使用）；应用退出时安全结束线程。
- 封面下载完成事件携带 `album_key`，UI 只在当前专辑匹配时替换，避免错图。

### 5.3 播放会话

`session.json`（与 `library.json` 分离，避免频繁写曲库）：

```json
{
  "schema": 1,
  "current_track_id": 123,
  "position": 42.5,
  "queue": [123, 456],
  "queue_index": 0,
  "view": "Library",
  "volume": 0.72,
  "saved_at": 1760000000
}
```

- 每 5–10s 或暂停/退出时原子写。
- 启动时校验文件存在；失效曲目跳过，保留其余队列。
- 恢复位置不超过时长−1s。

### 5.4 无缝播放

- 在曲目结束前预打开下一首 Decoder，建立下一段 `Source`。
- 使用自定义队列 Source 或双 Sink 方案，边界处切换元数据/UI，不重建整条音频链。
- 队列索引/循环/随机在边界处解析；跳过失败文件继续下一首。
- 保留 seek/暂停/音量；ReplayGain 在后续版本插入到 Source 链。
- 先做技术 spike：FLAC/WAV/MP3 三种格式、专辑连续曲目、20 次切歌无爆音/双播。

### 5.5 SMTC

- 使用 Windows `SystemMediaTransportControls`（WinRT/COM）。
- 同步：标题、艺术家、专辑、封面缩略图、播放状态、进度、可 seek。
- 事件：Play/Pause/Next/Previous/Stop/Seek。
- 任务栏/锁屏/蓝牙耳机/媒体键统一走 SMTC；无当前曲时清空。
- macOS 用 Now Playing/MPRIS 对应方案，v0.5 先 Windows。

### 5.6 文件夹监听

- 使用 `notify` crate（或 Windows ReadDirectoryChangesW）监听已添加目录。
- 防抖 1–2s；忽略临时文件/隐藏文件；只处理支持扩展名。
- 新增：解析标签后插入；修改：更新标签；删除：标记缺失；改名：按稳定 ID/路径处理。
- 网络盘：允许关闭监听，回退手动刷新。
- 扫描期间与监听事件合并，避免重复。

## 7. 验收标准

### 7.1 播放页

- [ ] 侧栏“正在播放”、底栏封面/标题、`F` 均可进入；Esc 返回。
- [ ] 有当前曲时显示封面/标题/艺术家/专辑/格式/时长/歌词/进度。
- [ ] 无当前曲时显示明确空状态，不出现空白歌词区。
- [ ] 点击歌词行可 seek；当前行高亮并居中。
- [ ] 纯文本歌词/无歌词/加载中/失败四种状态可区分。
- [ ] 940×640 不裁切；队列抽屉可关闭；200% DPI 正常。
- [ ] 封面/歌词加载不阻塞播放与滚动。

### 7.2 封面

- [ ] 内嵌封面优先于 `folder.jpg`；本地文件优先于网络。
- [ ] 自动匹配开启时，无封面曲目 ≤3s 显示网络封面（测试网络）。
- [ ] 匹配结果写入缓存；重启后直接显示，不重复请求。
- [ ] 关闭自动匹配后，播放无封面曲目不发起任何封面网络请求。
- [ ] 无结果/网络失败显示占位图与重试入口，不崩溃。
- [ ] 同一专辑多首曲目只发起一次查询/下载。
- [ ] 手动选择本地图片后立即显示并可清除。
- [ ] 封面来源标记正确；MusicBrainz 请求符合 1 req/s 与 User-Agent。
- [ ] 5MB/损坏图片/404 均有兜底。

### 7.3 无缝/会话/队列

- [ ] 测试专辑连续两首之间无可感知间隙（≤50ms）。
- [ ] 连续切 20 次无爆音、双播、错位。
- [ ] 重启恢复上次曲目/进度/队列/索引；失效项跳过。
- [ ] 队列拖动排序/移除/清空后持久化。
- [ ] 随机/循环/单曲循环在边界行为正确。

### 7.4 系统/曲库

- [ ] SMTC 显示标题/艺术家/专辑/封面/进度。
- [ ] 媒体键/锁屏/蓝牙耳机可播放/暂停/上下曲。
- [ ] 文件夹新增/删除/改名 ≤5s 反映；不触发全量重扫。
- [ ] 网络盘监听关闭时手动刷新可用。
- [ ] 退出/重启无残留线程/崩溃。

### 7.5 性能

- 1 万首：启动 ≤2s，播放页打开 ≤200ms，搜索 ≤100ms。
- 封面解码/模糊背景不造成持续掉帧；封面缓存命中无网络。
- 文件夹监听空闲 CPU 可忽略；扫描与监听并发不重复。

| 阶段 | 内容 | 产出 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| MusicBrainz 503/限速/网络不可达 | 封面匹配失败 | 串行队列、1 req/s、退避、负缓存、手动重试；失败不影响播放 |
| 中文/独立音乐在 CAA 覆盖低 | 匹配率不足 | 本地 `folder.jpg` 优先；提供选择本地图片；不抓商业平台 |
| 自动匹配错图 | 用户不信任 | 阈值 + 年份/时长/专辑类型评分；低置信不自动应用；候选选择 P1 |
| 无缝播放改动音频架构 | 爆音/双播/seek 异常 | 先 spike 三格式；保留旧路径回退；自动化 transition 测试 |
| SMTC COM 复杂 | 媒体键不生效 | 先做最小可用（播放/暂停/上下曲/元数据），再补 seek/封面 |
| 文件夹监听网络盘不稳定 | 重复扫描/CPU | 可关闭监听；防抖；忽略临时文件；手动刷新兜底 |
| 播放页封面模糊/大图卡顿 | 滚动掉帧 | 缩放到 512/1024、纹理缓存、切歌复用；只对封面做一次模糊 |
| 范围膨胀 | 延期 | 严格 P0/P1；ReplayGain/M3U/评分/标签编辑后移 |

## 10. 开放问题

1. 在线封面默认开启还是首次询问？建议默认开启，但设置中显著说明并允许一键关闭。
2. 自动匹配低置信时是否显示候选列表，还是只显示占位图？建议 v0.5 先占位+手动重试，v0.5.1 加候选。
3. 封面缓存是否允许用户“写入音乐文件夹为 `cover.jpg`”？建议只写应用缓存，避免修改用户文件。
4. 播放页是否在首次播放时自动打开？建议不自动，底栏给一次轻提示。
5. 队列恢复时，若来源歌单已删除，队列是否保留？建议保留为“临时队列”，标注来源失效。
6. 是否把 `settings` 从 `library.json` 拆出？建议 v0.5 暂不拆，v0.6 随 SQLite 一起重构。
7. MusicBrainz 的 `User-Agent` 具体联系地址/项目主页需在实现前确定。
8. macOS 的 Now Playing 是否与 Windows SMTC 同版交付？建议 Windows 先行，macOS 在 v0.8 平台版补齐。
