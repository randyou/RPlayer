## 1. 为什么是 v0.6

v0.5 解决的是“播放体验”：

- 有常驻正在播放侧栏和全屏歌词页；
- 有无缝播放、会话恢复、队列拖动；
- 有本地/在线封面、文件夹监听、SMTC 媒体卡。

但曲库仍然主要是**一张长表格**：

- 不能按专辑封面浏览，也不能进入艺术家页；
- 没有评分、播放次数、跳过次数，无法回答“我最常听什么”“哪些好歌很久没听”；
- 没有智能歌单，不能按规则自动组织音乐；
- 批量选择只有勾选模式，不能 Shift/Ctrl 多选、拖到歌单；
- 没有标签编辑、缺失文件/重复歌曲检查；
- v0.5 还留下 SMTC 应用名/封面、ReplayGain、M3U、歌词偏移等尾巴。

v0.6 的目标不是继续加播放特效，而是让 RPlayer **能管理一个真实规模的本地曲库**。

## 2. 版本目标

### 2.1 目标

- 用户可以用“歌曲 / 专辑 / 艺术家”三种方式浏览曲库。
- 用户能给歌曲评分，系统自动记录播放/跳过/最近播放。
- 用户可以创建智能歌单，并按规则实时更新。
- 用户可以用 Shift/Ctrl 多选、拖拽到歌单/队列，批量操作。
- 用户可以检查缺失文件、重复歌曲、空标签等曲库问题。
- 用户可以在 RPlayer 内修正常见标签，不再依赖外部工具。
- 收尾 v0.5：SMTC 应用名/封面、ReplayGain、M3U、歌词偏移。

### 2.2 非目标

- 在线音乐、账号、云同步、社交。
- 移动端。
- CD 抓轨、音频转码、文件批量重命名/整理（放 v0.7）。
- 插件市场、VST/DSP 链、可视化。
- WASAPI 独占、ASIO、输出设备选择、交叉淡化（v0.7）。
- DLNA/AirPlay/Chromecast。
- 歌词在线编辑平台、歌词社区。

## 5. 详细需求

### 5.1 专辑与艺术家浏览（LIB-20/21/22）

**专辑视图**

- 顶部提供「歌曲 / 专辑 / 艺术家」分段切换，不新增过多侧栏项。
- 专辑网格：封面、专辑名、艺术家、年份、曲目数。
- 封面尺寸随窗口自适应，默认 160–180px，最小 120px。
- 双击专辑：播放整张；右键：播放、加入队列、加入歌单、查看详情。
- 专辑详情：大封面、专辑信息、曲目列表、播放全部、加入队列、评分汇总。
- 排序：专辑名、艺术家、年份、添加时间、播放次数。
- 筛选：艺术家、年份、流派、有无封面。

**艺术家视图**

- 艺术家网格/列表：头像（暂无则用首字母）、专辑数、曲目数。
- 艺术家详情：专辑分区 + 全部曲目；播放全部/随机。
- 多艺术家合作曲目归入主要艺术家，详情页显示合作者。

**封面缩略图**

- 新增封面缩略图管理器：按专辑 key 缓存 256/512 像素纹理。
- 只对可见区域加载，滚动时取消/排队；限制并发（2–4）。
- 内存上限（例如 200 张缩略图），超出 LRU 释放。
- 不重复解码；网络封面失败使用占位图，不阻塞滚动。

**验收**

- 1000 张专辑首次滚动不卡顿、无持续掉帧；封面渐进出现。
- 已缓存封面再次进入 <500ms 显示。
- 专辑/艺术家视图切换不丢当前播放、队列和滚动位置（可接受重置到顶部）。
- 空专辑/未知艺术家有明确分组，不崩溃。

### 5.2 评分与播放统计（STAT-01/02/03）

**评分**

- 0–5 星，0 表示未评分；点击星星评分，再点当前星可清除。
- 表格行、正在播放页、专辑详情都可评分。
- 支持批量评分；支持按评分筛选/排序。
- 评分变化立即持久化，不重写音频标签（v0.6 先存 RPlayer 数据）。

**播放统计**

- `play_count`：播放超过 50% 或 30 秒（取较小值）记一次；同一曲目单次播放只记一次。
- `skip_count`：开始播放后 30 秒内切歌/停止，记一次跳过；拖动到最后不算跳过。
- `last_played_at`、`last_skipped_at`、`first_played_at`。
- 重复播放/循环不重复计数，直到重新开始。
- 统计写入独立 `playback_stats.json`，5 秒防抖/退出保存，避免频繁重写曲库。
- 表格可显示播放次数、最近播放；默认隐藏，可在列设置开启（若列太多，先做详情页）。

**验收**

- 播放 10 秒切歌：skip+1，play 不变。
- 播放超过 50%：play+1；暂停/继续不重复。
- 单曲循环一首 3 次：play+3，不重复同一次。
- 重启后统计、评分、最近播放一致。
- 10 万次统计写入不阻塞 UI。

### 5.3 智能歌单（SMART-01/02/03）

**规则字段**

- 文本：标题、艺术家、专辑、流派、格式、文件夹路径。
- 数值：年份、时长、评分、播放次数、跳过次数。
- 日期：添加时间、最近播放、最近跳过。
- 布尔/枚举：是否收藏、是否有封面、是否有歌词。

**操作符**

- 文本：是、包含、开头是、结尾是、不是。
- 数值：=、>、>=、<、<=、介于。
- 日期：最近 N 天/周/月、早于、晚于。
- 组合：全部满足（AND）/任一满足（OR）/排除（NOT）；最多 10 条规则。
- **从未播放**：`last_played` 为空视为“从未播放”，默认匹配“早于/最近 N 天未听”；提供“包含从未播放”开关，避免把新歌误排除。

**构建器**

- 弹窗内添加/删除规则，实时显示“匹配 N 首”。
- 排序字段与方向、数量限制（如前 50 首）。
- 保存为智能歌单，侧栏与普通歌单并列，使用不同图标。
- 智能歌单不可手动增删歌曲；可“复制为普通歌单”。
- 规则可编辑、复制、删除；删除需确认。

**实时更新**

- 评分、播放统计、曲库增删、标签编辑后，相关智能歌单在 1 秒内刷新。
- 空结果有明确空状态，不自动删除歌单。
- 求值 1 万首 <100ms；5 万首 <300ms，否则引入索引/缓存。

**验收**

- 创建“4 星以上 + 半年没听 + 爵士”得到正确结果。
- 修改一首歌评分后，智能歌单立即增加/移除。
- 规则排序/限制正确；清空规则不能保存。
- 删除智能歌单不影响普通歌单和歌曲。

### 5.4 多选与拖拽（SEL-01/02）

- 表格支持单击选中、Ctrl/Command 切换、Shift 范围选择。
- 顶部出现批量操作条：已选 N 首、加入歌单、加入队列、评分、移除。
- 支持 Ctrl+A 全选当前筛选结果；Esc 清除选择。
- 拖动歌曲到侧栏歌单/队列；拖动多首先显示数量。
- 拖动到歌单时去重，提示“已添加 N 首，跳过 M 首重复”。
- 保留现有“批量勾选”模式或将其合并为统一多选，不能两套状态并存。
- 右键菜单与批量操作一致。

**验收**

- Shift 选择 100 首后加入歌单，顺序与表格一致。
- 拖到队列后当前播放不中断。
- 切换视图/搜索后选择状态符合预期（默认清空或保留当前可见）。

### 5.5 曲库健康检查（HEALTH-01/02）

**检查项**

- 文件不存在/路径失效。
- 无法解码/读取标签失败。
- 标题/艺术家/专辑为空。
- 时长为 0 或异常短（<3 秒）。
- 重复候选：标题+艺术家相同，时长差 ≤2 秒；或同路径重复。
- 封面缺失/歌词缺失统计（只统计，不自动处理）。

**交互**

- 扫描在后台进行，显示进度；可取消。
- 结果分组展示，支持“在文件夹中显示”“从曲库移除”“忽略”。
- 重复项只提示，不自动删除；默认保留先添加/较高码率（仅建议）。
- 结果可导出 CSV（P2）。

**验收**

- 删除一个音频文件后运行检查，能定位失效记录。
- 复制同一文件两份，能识别为重复候选。
- 移除失效记录不影响收藏/歌单中的其他歌曲。
- 检查 1 万首 <10 秒（不含解码）。

### 5.6 标签编辑（TAG-01/02/03）

**支持字段**

### 5.13 系统托盘与关闭到托盘（SYS-03）

**目标**

- 用户点窗口关闭按钮时，RPlayer 可以隐藏到系统托盘，播放继续。
- 托盘图标提供常用控制，不必重新打开主窗口。
- 从托盘“退出”才是真正结束进程，并保存播放会话/曲库。

**行为定义**

- 默认：**关闭窗口 → 隐藏到托盘**；设置中提供“关闭窗口时最小化到托盘”开关。
- 关闭到托盘时：
  - 主窗口隐藏，任务栏按钮消失；
  - 音频继续播放；
  - 桌面歌词/迷你播放器保持当前状态，不强制关闭；
  - 首次隐藏时弹一次轻提示“RPlayer 仍在托盘运行”。
- 托盘双击：显示并聚焦主窗口；再次双击可隐藏（可选）。
- 托盘右键菜单：
  - 显示主窗口
  - 播放 / 暂停
  - 上一首 / 下一首
  - 桌面歌词开关
  - 迷你播放器开关
  - 设置
  - 退出 RPlayer
- 托盘 tooltip 显示当前歌名 — 艺术家；无播放时显示 RPlayer。
- 托盘“退出”：
  - 保存 `library.json`、`session.json`；
  - 结束 SMTC helper；
  - 真正退出进程；
  - 不能再次被“关闭到托盘”拦截。
- Windows 注销/关机时直接退出，不阻止系统关机。
- 单实例：托盘状态下再次启动 RPlayer，应恢复已有窗口而不是启动第二个进程（依赖 SYS-06；若 v0.6 未完成，至少避免重复托盘图标）。

**设置**

- “关闭窗口时最小化到托盘”默认开。
- 可选“启动后最小化到托盘”（P2，默认关）。
- 托盘图标使用 UI-13 的同一套 RPlayer 图标。

**实现建议**

- Windows 使用 `tray-icon` + `muda`（或原生 `Shell_NotifyIcon` + 菜单）；托盘事件通过 channel 进入 UI 线程。
- eframe 的 `close_requested` 拦截：调用 `ViewportCommand::CancelClose` + `ViewportCommand::Visible(false)`；用 `allow_exit` 标志区分“托盘退出”。
- 托盘菜单动作复用现有 `MediaCommand`/`toggle_*` 方法，避免复制播放逻辑。
- 退出顺序：保存 → 关闭 overlay viewports → 停止 helper → 退出。
- macOS 使用菜单栏图标（P2，后置）。

**验收**

- 点关闭后窗口消失、进程仍在、播放不中断；托盘图标存在。
- 双击托盘恢复主窗口并聚焦；再次关闭仍可隐藏。
- 托盘菜单播放/暂停、上下曲、桌面歌词、迷你播放器、设置均生效。
- 托盘“退出”后进程、音频、SMTC helper 全部结束，且会话已保存。
- 重启后恢复到退出前的歌曲/进度。
- 反复隐藏/显示 20 次不产生重复托盘图标、不泄漏线程。
- 125%/200% DPI 下托盘图标清晰；Windows 10/11 任务栏溢出区可见。
- 关闭到托盘开关关闭时，关闭按钮恢复为正常退出。

**依赖**

- UI-13 图标资源。
- SYS-06 单实例（建议同批完成；否则托盘状态下重复启动会产生两个进程）。
- SMTC helper 的退出生命周期。

- `src/app/settings.rs`：主题选择卡片/预览。
- `src/app/library_view.rs`、`now_playing.rs`、`now_rail.rs`、`overlay.rs`：移除硬编码色。

### 5.16 AI / Agent 可操作性（AI-01/02/03）

**目标**

让 AI 大模型/自动化 Agent 能**稳定理解并操作** RPlayer，而不是依赖截图坐标猜测：

- 每个功能有可读名称、角色、状态；
- 核心任务可以只用键盘/无障碍树完成；
- 动作有稳定 ID，不随界面排版变化；
- 提供可控的状态读取与本地控制入口；
- 危险操作有确认，不允许 Agent 绕过。

> 本任务不做内置 LLM、不做云端 AI、不做自主文件删除。只做“可被 Agent 操作的界面与接口”。

**AI-01：语义化 UI（P0）**

- 启用 eframe/egui 的 AccessKit 支持。
- 所有自绘控件补 `WidgetInfo`：
  - `icon_button`：角色 Button，名称如“播放 / 暂停”“上一首”“下一首”“打开设置”；
  - `nav_item`：角色 Tab/ListItem，名称 + 选中状态 + 数量；
  - `track_table` 行：角色 ListItem，名称“歌名 — 艺术家”，选中/播放状态；
  - `seek_bar`：角色 Slider，当前值/最大值/可调整；
  - `toggle_switch`：角色 Switch，开启/关闭；
  - 主题卡片/评分星/队列行同样补名称与状态。
- 图标按钮不能只有 tooltip；必须有可读标签。纯图标操作要同时出现在右键菜单/命令面板。
- 所有 hover-only 操作要有非 hover 入口；拖拽排序要有菜单“上移/下移/移到顶部”作为替代。
- 错误提示必须包含下一步动作，例如“文件不存在：重新扫描 / 从曲库移除”，而不是只有“失败”。
- 按钮使用稳定中文名称，避免“确定/好的/...”这类无语境文案；破坏性按钮明确写“删除歌单”“移除 3 首歌曲”。

**AI-02：命令面板与稳定动作 ID（P1）**

- `Ctrl+K` 打开命令面板，可搜索：
  - 播放/暂停、上一首/下一首；
  - 搜索歌曲、打开专辑/艺术家；
  - 加入队列、加入歌单、收藏、评分；
  - 切换主题、打开设置/均衡器/桌面歌词/迷你播放器；
  - 重新扫描、下载歌词、匹配封面。
- 每个动作有稳定 ID（不翻译、不随 UI 改动）：
  - `player.play_pause`
  - `player.next`
  - `player.previous`
  - `library.search`
  - `queue.add`
  - `playlist.add`
  - `lyrics.download`
  - `cover.refresh`
  - `settings.open`
  - `theme.set`
- 命令面板显示动作名称、快捷键、当前是否可用；不可用给原因（如“未在播放”）。
- 动作注册表是单一来源：按钮、菜单、快捷键、命令面板调用同一个 `Action` 枚举/函数，避免行为分叉。
- 命令面板支持键盘上下选择、Enter 执行、Esc 关闭；搜索结果高亮匹配片段。
- 中文/英文别名：如“播放全部 / Play all”“设置 / Settings”。

**AI-03：本地控制接口（P2，安全优先）**

- 提供 `rplayer-cli` 或本地回环 IPC/HTTP，默认关闭，需在设置中显式开启。
- 只绑定 `127.0.0.1`，使用随机令牌；不监听公网。
- 命令示例：
  - `state --json`：当前歌曲、进度、播放状态、音量、主题、队列长度、视图；
  - `play --query "一千年以后"`；
  - `pause` / `next` / `previous`；
  - `queue add --query ...`；
  - `playlist add --name ... --query ...`；
  - `lyrics download`；
  - `theme set paper`。
- 写操作有速率限制；删除/清空等破坏性动作默认拒绝，必须显式 `--confirm` 且仍走 UI 确认。
- 不暴露文件系统任意路径写入；导入文件夹只允许用户已授权目录。
- 所有请求记录本地日志（可关闭），不包含歌词/音频内容。

**验收**

- 用 agent-desktop/UI Automation 快照能读到：播放/暂停、上一首、下一首、搜索框、曲库行、设置、关闭、主题、队列等控件名称与状态。
- 仅用键盘完成：搜索→播放→暂停→下一首→加入歌单→切换主题→打开设置。
- 命令面板能搜索并执行至少 15 个核心动作；动作 ID 与按钮行为一致。
- 未播放时“下一首/暂停”等动作有禁用原因，不静默失败。
- 破坏性动作必须确认；Agent 不能通过命令面板/CLI 绕过。
- 本地接口默认关闭，开启后只回环可访问；令牌错误拒绝。
- 无坐标点击也能完成核心任务；视觉布局变化不破坏动作 ID。

**实现位置**

- `src/app/actions.rs`（新）：`Action` 枚举、动作注册表、执行入口。
- `src/app/command_palette.rs`（新）：Ctrl+K 搜索/执行。
- `src/app/widgets`/`src/ui/widgets.rs`：`WidgetInfo` 语义标签。
- `src/app/library_view.rs`：表格行、按钮、右键菜单语义。
- `src/platform/automation.rs`（新，P2）：回环 CLI/API、令牌、状态快照。
- `Cargo.toml`：eframe `accesskit` feature（若当前未启用）。

## 6. 数据模型建议

### 6.1 播放统计

独立文件 `playback_stats.json`：

```json
{
  "schema": 1,
  "tracks": {
    "123456": {
      "rating": 4,
      "play_count": 12,
      "skip_count": 3,
      "first_played_at": 1760000000,
      "last_played_at": 1760000000,
      "last_skipped_at": 1760000000
    }
  }
}
```

- 评分/统计不写音频标签，避免误改文件。
- 5 秒防抖保存；退出保存。
- 曲目移除后统计保留 30 天（可恢复），或提供清理。

### 6.2 智能歌单

```json
{
  "id": 42,
  "name": "半年没听的爵士",
  "kind": "smart",
  "match": "all",
  "rules": [
    {"field": "genre", "op": "contains", "value": "Jazz"},
    {"field": "rating", "op": ">=", "value": 4},
    {"field": "last_played", "op": "older_than_days", "value": 180}
  ],
  "sort": {"field": "last_played", "desc": true},
  "limit": 100
}
```

- 普通歌单保持 `kind: normal`，迁移旧数据默认 normal。
- 规则字段/操作符使用枚举，序列化稳定。

### 6.3 专辑/艺术家

- 不新增独立数据库表；按 `artist + album` 归一化聚合。
- 专辑 key 与封面缓存 key 一致；艺术家按主要艺术家归一化。
- 若后续 5 万首性能不足，再引入 SQLite 索引（v0.6.1 评估）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 专辑封面大量解码卡顿 | 浏览体验差 | 缩略图缓存、可见区加载、并发限制、LRU |
| 统计写太频繁 | 磁盘/UI 卡顿 | 独立 stats 文件、5s 防抖、退出保存 |
| 智能歌单规则膨胀 | 求值慢/UI 复杂 | 最多 10 条规则；先 AND/OR；性能基准 |
| 标签写坏文件 | 用户数据风险 | 字段备份、写后校验、失败回滚、只支持安全格式 |
| 批量标签误覆盖 | 数据丢失 | 只写用户修改字段；预览变更；二次确认 |
| 重复检测误报 | 用户误删 | 只提示不自动删除；保留建议；可忽略 |
| JSON 曲库规模 | 5 万首启动慢 | v0.6.0 基准；必要时 SQLite/索引 |
| SMTC 应用身份 | 仍显示未知应用 | AUMID/快捷方式/版本资源三选一验证 |
| CAA 网络不可达 | 在线封面失败 | 手动本地封面、明确失败状态、网络可用时复验 |
| `winresource` 在 GNU 工具链下缺 `windres` | exe 资源编译失败 | 优先使用 `embed-resource`/系统 `windres`；在 Windows GNU 与 MSVC 各验证一次 |
| 托盘与 eframe 关闭事件冲突 | 关窗无法隐藏/退出 | `allow_exit` 标志 + `CancelClose`；托盘退出走独立退出路径 |
| 托盘菜单线程与 UI 线程 | 菜单动作不生效/卡死 | 托盘事件只发 channel，所有播放操作回 UI 线程执行 |
| 按钮 padding 一刀切 | 表格/图标按钮被放大，密度下降 | 按主/次/胶囊/图标四类 token；截图回归 |
| 主题扩展后仍有硬编码色 | 换主题“只换一半” | 颜色全部走 token；每套主题做页面矩阵检查 |
| 主题数量膨胀 | 维护/测试成本上升 | 首版固定 6 套预设，不做皮肤引擎 |
| egui 自绘控件未暴露 Accessibility | Agent 仍只能按坐标 | 启用 AccessKit；逐个自绘控件补 WidgetInfo 并快照验收 |
| 命令面板与按钮行为分叉 | AI 执行结果不一致 | 统一 Action 枚举，按钮/菜单/快捷键/面板共用 |
| 本地控制接口被滥用 | 非授权操作/隐私 | 默认关闭、回环绑定、随机令牌、破坏性动作确认/拒绝 |
| 单实例未完成 | 托盘状态重复启动 | 与 SYS-06 同批；至少加进程互斥/命名事件 |
| 范围过大 | 延期 | 严格 v0.6.0/0.6.1/0.6.2；P2 不阻塞 |

## 10. 开放问题

1. 目标曲库上限是 1 万、5 万还是 10 万？决定是否本版引入 SQLite。
2. 评分是否写回音频标签？建议只存 RPlayer 数据，避免误改。
3. 播放统计是否允许用户重置/导出？建议提供单曲重置与清空全部。
4. 智能歌单是否需要“随机 N 首”与“按年代分组”？可放 P2。
5. 标签编辑是否支持封面写入？建议 v0.6 先不做，避免版权与误写。
6. 是否允许编辑正在播放的文件？建议允许，但写后重新加载并提示。
7. 健康检查的重复判定是否加入音频指纹？v0.6 先做元数据+时长，指纹 P2。
8. SMTC 应用身份是否必须依赖安装包/快捷方式？便携版如何注册？
9. CAA 在线封面是否需要第二开放源？先不接商业平台，保留本地兜底。
10. v0.6 是否包含 macOS 验证？建议放平台版本。
11. 关闭按钮默认“隐藏到托盘”还是“退出”？建议默认隐藏，并在设置中可改为退出；首次隐藏提示一次。
12. 托盘是否常驻显示播放控制，还是只保留菜单？建议菜单完整、双击恢复，避免托盘区域拥挤。
13. 主题首版做 4 套还是 6 套？建议 6 套（3 浅/3 深），强调色先随预设，不做完全自定义。
14. `Ctrl+T` 是切换浅/深模式，还是循环主题预设？建议保留“切换模式”，预设选择放设置，避免误触。
15. AI 可操作性的首选入口是 AccessKit/UI Automation、命令面板，还是本地 CLI？建议先做前两项，CLI 作为 P2。
16. 本地控制接口是否需要跨设备/局域网？建议只做回环；跨设备属于远程控制，需单独安全设计。
17. 是否允许 Agent 执行删除/清空？建议默认拒绝，必须人工在 UI 确认。

## 12. 结论

v0.6 的核心不是“再加一个页面”，而是把 RPlayer 从**播放器**升级为**可长期维护的本地曲库**：
