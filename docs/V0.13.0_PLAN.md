# v0.13.0 · 发布工程与文档校准

## 目标

消除版本号的多处手工同步，修正 exe 元数据，并把发布流程固化成可重复执行的检查清单。

本版本不改变播放、曲库和歌词行为，风险集中在构建资源和文档。

## 背景

- `build.rs` 的 `FileVersion` / `ProductVersion` 停留在 `0.12.6.0`，而 Cargo 和 UI 已经是 `0.12.9`。
- 侧栏、设置、关于各自硬编码版本号，发布时容易漏改。
- README 的特性列表缺少 v0.8–v0.12 的桌面歌词、CUE、歌词编辑、曲库维护等能力。
- AGENTS 的歌词优先级仍是旧规则，与当前“用户编辑优先”不一致。

## 实现

1. **版本单一来源**
   - UI 使用 `env!("CARGO_PKG_VERSION")`。
   - `build.rs` 读取 `CARGO_PKG_VERSION`，去掉预发布/构建后缀后生成 `x.y.z.0`。
   - 不再在源码中硬编码版本字符串。

2. **发布检查清单**
   - 新增 `docs/RELEASE_CHECKLIST.md`。
   - 覆盖测试、构建、版本核对、dist 更新、zip 完整性、SHA-256、提交。

3. **文档校准**
   - README 增加 v0.8–v0.12 摘要与 v0.13.0 版本记录。
   - 补充歌词编辑、CUE、曲库维护、批量撤销等特性。
   - AGENTS 更新模块表、版本规则和歌词优先级。
   - README 增加 `docs/ROADMAP.md` 链接。

## 手工验收

1. 启动 release，检查侧栏底部版本。
2. 打开设置，检查底部版本。
3. 打开关于，检查副标题版本。
4. 右键 `RPlayer.exe` → 属性 → 详细信息，检查文件版本/产品版本。
5. 确认主界面、设置、关于布局没有因版本字符串变长而错位。

## 风险

- `winresource` 对版本字符串格式敏感；只接受数字点分版本。`build.rs` 已去掉 `-`/`+` 后缀。
- 本版本不运行 `cargo fmt --all`，避免再次产生整树格式化 diff。
